# 2026-05-16 會員系統 JWT 驗證

## 1. User Story

作為一個使用者，我希望能夠註冊帳號、登入後取得 JWT Token，並透過 Token 存取受保護的 API，以確保個人飲食紀錄的安全性與隱私。

**核心變更**：新增四支 auth 端點（register / login / refresh / me），以 JWT Access Token（15m）+ Refresh Token（7d）作為驗證機制。

---

## 2. 測試流程驗證 (Test Flow)

1. **準備環境**
   - Docker MySQL 已啟動
   - `.env` 已設定 `JWT_SECRET`、`JWT_REFRESH_SECRET`
   - `npx prisma migrate dev --name add-auth-fields` 完成
   - `npm run dev:server` 啟動後端

2. **操作路徑**
   - POST `/api/auth/register` → 取得 userId
   - POST `/api/auth/login` → 取得 accessToken + refreshToken
   - GET `/api/auth/me`（Bearer token）→ 取得使用者資訊
   - POST `/api/auth/refresh` → 換發新 token

3. **預期結果**
   - register 201，無 password 欄位洩漏
   - login 200，回傳 accessToken + refreshToken + user
   - me 200（有 token）/ 401（無 token）
   - refresh 200（有效）/ 401（無效或舊 token）

4. **最終確認**
   - 重複 email 註冊回傳 409
   - 錯誤密碼登入回傳 401
   - 舊 refreshToken（已被換掉）回傳 401

## 3. Spec 與架構設計

### 3.1 技術細節

- **密碼雜湊**：bcryptjs，saltRounds=10
- **Access Token**：JWT，payload `{ userId, email }`，15m 有效，SECRET=`JWT_SECRET`
- **Refresh Token**：JWT，payload `{ userId }`，7d 有效，SECRET=`JWT_REFRESH_SECRET`，登入時寫入 DB
- **Refresh Token 輪換**：每次 `/refresh` 都產生新 token 對並更新 DB，舊 token 立即失效（防止 replay）

### 3.2 路由與 API 端點

| 方法 | 路徑 | 說明 | 驗證 |
|---|---|---|---|
| POST | `/api/auth/register` | 註冊 | 無 |
| POST | `/api/auth/login` | 登入，回傳 token | 無 |
| POST | `/api/auth/refresh` | 換發新 token | refreshToken in body |
| GET  | `/api/auth/me` | 取得目前使用者 | Bearer Token |

### 3.3 資料庫變動

User model 新增：
- `password String?` — bcrypt hash，null 為舊有自動建立的使用者
- `refreshToken String?` — 登入時寫入，refresh 時更新

---

## 4. 環境與設定 (.env)

```
JWT_SECRET=<64 字元隨機字串>
JWT_REFRESH_SECRET=<另一組 64 字元隨機字串>
JWT_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=7d
```
