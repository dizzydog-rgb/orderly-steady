# Architecture

本文件描述「控糖網站」(Glucose Control Web) 的架構設計、目錄結構與核心演算法邏輯。

## 1. 系統概述
本專案是一個基於 Vue 3 + TypeScript 的前端應用，旨在協助使用者透過記錄進食順序來管理血糖。核心價值在於提供即時的「進食順序評分」，引導使用者建立先纖維、後蛋白質、最後碳水化合物的飲食習慣。

## 2. 目錄結構
依據專案現況與擴展性預期，目錄結構定義如下：

- `src/`
  - `assets/` - 靜態資源（圖片、圖示）。
  - `components/` - 可複用的 UI 元件。
  - `composables/` - 封裝 Vue Composition API 邏輯（如 `useGlucoseScore`）。
  - `services/` - 核心業務邏輯與演算法。
    - `scoringAlgorithm.ts` - 進食順序評分演算法核心。
  - `types/` - TypeScript 介面與型別定義。
  - `views/` - 頁面級元件（未來擴展路徑）。
  - `App.vue` - 根組件。
  - `main.ts` - 入口文件。

## 3. 進食順序評分演算法 (Meal Order Scoring Algorithm)

### 3.1 設計概念
血糖控制的關鍵在於延緩碳水化合物的吸收速度。研究顯示，先攝取膳食纖維（蔬菜）與蛋白質，能在腸胃形成緩衝，有效平抑餐後血糖波動。

### 3.2 評分規則與權重
演算法將食物分為四大類，並根據其在進食序列中的位置給予加權或扣分：

| 食物分類 | 代碼 | 理想順序 | 權重 (Base Score) |
| :--- | :--- | :--- | :--- |
| 膳食纖維 (Fiber) | `F` | 1 | 40 |
| 蛋白質 (Protein) | `P` | 2 | 30 |
| 複合碳水 (Complex Carb) | `CC` | 3 | 20 |
| 精緻糖/精緻碳水 (Simple Carb) | `SC` | 4 | 10 |

### 3.3 演算法公式
最終評分 $S$ 計算如下：

$$S = \sum_{i=1}^{n} (Base_i \times Modifier_i)$$

其中 $Modifier_i$ 根據位置 $i$ 與分類的匹配程度決定：
- **正確位置 (Order Match)**: 若分類符合理想順序，則 $Modifier = 1.0$。
- **早熟扣分 (Premature Penalty)**: 若碳水 (`CC`, `SC`) 出現在纖維 (`F`) 之前，該項 $Modifier = 0.5$。
- **緩衝加成 (Buffer Bonus)**: 若在吃碳水前已攝取足夠纖維（如 $i > 2$ 且前兩項含 `F`），碳水項 $Modifier = 1.2$。

### 3.4 範例計算
- **案例 A (優良):** `F` -> `P` -> `CC`
  - 評分：$40(1.0) + 30(1.0) + 20(1.2) = 40 + 30 + 24 = 94$
- **案例 B (普通):** `P` -> `F` -> `CC`
  - 評分：$30(1.0) + 40(1.0) + 20(1.0) = 90$
- **案例 C (不佳):** `CC` -> `F` -> `P`
  - 評分：$20(0.5) + 40(1.0) + 30(1.0) = 10 + 40 + 30 = 80$

## 4. 資料流
1. **輸入層**: 使用者透過 UI 選擇食物與進食順序。
2. **處理層**: `useGlucoseScore` composable 呼叫 `scoringAlgorithm.ts` 進行即時計算。
3. **表現層**: 顯示百分制分數、視覺化顏色提醒（綠/黃/紅）與建議改善語句。

## 5. 擴展考慮
- **時間間隔**: 考慮兩類食物之間的時間差（如：先吃菜 15 分鐘後再吃肉，分數更高）。
- **GI 值整合**: 引入具體食物的 GI 值來微調 Base Score。
- **歷史趨勢**: 對接資料庫以追蹤長期飲食習慣對分數的影響。
